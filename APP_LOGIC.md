# Техническая спецификация системы «Маршрутные листы» (Final TWA-First Edition)

Данный документ является финальной спецификацией архитектуры. Основной интерфейс водителя — **Telegram Mini App (TWA)**. Основной интерфейс менеджера — **Web-панель (ПК)**.

---

## 1. Интерфейс водителя (Mini App)

### 1.1. Аутентификация и Безопасность
- Приложение автоматически распознает пользователя через `window.Telegram.WebApp.initData`.
- **Валидация**: Каждый запрос от TWA к серверу сопровождается строкой `initData`. Сервер проверяет подпись `hash` с использованием `TELEGRAM_BOT_TOKEN`, чтобы исключить подмену ID пользователя.
- **Роутинг**: Приложение разделено на `/admin` (менеджер) и `/app` (водитель).

### 1.2. Сценарии (Roadmaps)
1. **Регистрация**: Форма (ФИО, Телефон, Авто, Номер авто). Данные сохраняются в `registrationRequests`.
2. **Рабочая смена**:
   - **Старт**: Ввод начального пробега.
   - **Коррекция**: Водитель может изменить начальный пробег до тех пор, пока не добавлена первая точка маршрута.
   - **Маршрут**: Голосовой ввод адреса -> Распознавание (Web Speech API) -> Поиск координат (Nominatim).
   - **Расчет пути**: Использование OSRM. В случае недоступности сервиса — расчет по прямой (Haversine formula) с коэффициентом 1.2.
   - **Документы**: Съемка фото -> Сжатие на стороне клиента (до 2Мб) -> Отправка через Cloud Function в Telegram-архив.
   - **Финиш**: Ввод конечного пробега. Проверка: `конечный > начальный`.

---

## 2. Интерфейс менеджера (Web)

Доступен через браузер (`/admin`) для пользователей с ролями `admin`/`secretary`.
1. **Заявки**: Просмотр и одобрение новых водителей. Привязка водителя к теме в Telegram.
2. **История смен**:
   - Интерактивная карта (Leaflet) для каждой смены.
   - Список всех точек `trips` с временными метками.
   - Сравнение: «Пробег по одометру» vs «Расчетный пробег по GPS».

## 3. Модель данных (Firestore)

### 3.1. Коллекция `shifts`
- `driverId`: Ссылка на водителя.
- `startThreadId`: ID темы в Telegram на момент начала смены (фиксируется для текущей смены).
- `startMileage`, `endMileage`, `distance`.
- `totalTripDistance`: Сумма дистанций из коллекции `trips`.
- `status`: `active`/`completed`.

### 3.2. Коллекция `trips`
- `shiftId`: Ссылка на смену.
- `address`: Текстовый адрес.
- `lat`, `lon`: Координаты.
- `distanceFromPrev`: Дистанция от предыдущей точки (в км).
- `createdAt`: Время фиксации.

## 4. Технические ограничения и риски

### 4.1. Работа с фото
- Чтобы избежать перегрузки памяти Cloud Functions (OOM), изображения сжимаются в браузере (Canvas API) перед отправкой.
- Файлы не хранятся в Firebase Storage, а передаются в Telegram Bot API методом `multipart/form-data`.

### 4.2. Геокодирование (Nominatim)
- Лимит Nominatim — 1 запрос в секунду. Для 4 водителей этого достаточно, но в коде предусмотрена задержка (debounce) при поиске адреса.

### 4.3. Изоляция данных
- Firestore Rules настроены так, что водитель может видеть только свои данные (через проверку `request.auth.token.firebase.identities['telegram.org'][0]`), а менеджер — все данные.
